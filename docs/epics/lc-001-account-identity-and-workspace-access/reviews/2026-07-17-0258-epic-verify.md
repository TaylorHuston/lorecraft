## Findings

### BLOCKING

- None.

### REQUIRED

1. **Superseded catalog ownership (`scope-drift`, `superseded-truth-drift`)**
   - References: `epic.md` Outcome, Current Scope, and S3 Story Index row.
   - Impact: LC-001 claims empty World-catalog behavior even though S3 no longer has that Requirement and explicitly assigns it to `LC-002/S1`.
   - Remediation: remove empty-catalog ownership from LC-001 and describe S3 as protected access and sign-out only. This is an artifact-only fix.

2. **Accepted security behavior lacks Requirements and Scenarios (`requirement-drift`, `verification-drift`)**
   - References: S1 and S2 Verified By tables, Cross-Story Concerns, `account_security.spec.ts`, and `auth_request_boundary_middleware.ts`.
   - Impact: CSRF rejection, JSON/16 KB request limits, throttling, value-preserving recovery, and no-mutation guarantees are implemented and tested but mapped onto signup/sign-in Scenarios that do not declare those outcomes.
   - Remediation: add stable security/recovery Requirements and Scenarios under S1/S2 or introduce explicitly identified cross-story Requirements, then remap existing evidence. Existing behavior is sufficient; no runtime implementation is currently indicated.

3. **Session-loss and logout-failure paths are missing from S3 (`requirement-drift`, `verification-drift`)**
   - References: S3 R1/R2, `App.test.tsx`, World/Adventure route tests, and backend CSRF evidence.
   - Impact: protected API 401 responses terminate client session state, while failed logout preserves the authenticated session, but neither behavior has a matching Scenario. Failure tests are mapped to successful sign-out.
   - Remediation: add `Protected Request Detects Session Loss` and `Sign-Out Fails Safely` Scenarios and remap the existing proof.

4. **Removed Scenario remains in test traceability (`superseded-truth-drift`, `verification-drift`)**
   - Reference: `apps/frontend/src/app/App.test.tsx` test labeled `LC-001/S3/R3-S1`.
   - Impact: the test points to a nonexistent LC-001 Scenario after empty-catalog ownership moved to `LC-002/S1/R1-S3`.
   - Remediation: relabel the test to the LC-002 reference. Because this edits a test source file, address it through a small SDD Change rather than post-audit artifact editing.

5. **Stale destination, Change link, and implementation map (`artifact-drift`, `status-drift`)**
   - References: S1/S2 `Your Worlds`, Product Context UI-cleanup path, and S3 Implemented By.
   - Impact: current UI says `Worlds`; the UI-cleanup Change is under `docs/changes/closed/`; and the protected-route map understates World/Adventure and account-owned cache boundaries.
   - Remediation: use neutral authenticated World-workspace wording, repair the closed path, add the PRD reference, and update the implementation map.

6. **Verification gaps contradict their own deferrals (`verification-drift`, `template-drift`)**
   - References: S1/S2 `Verification Gaps: None`, their separate `Deferred Verification` sections, and Cross-Story Deferred Verification.
   - Impact: production HTTPS verification of the cookie `Secure` attribute and a dedicated Neon provider smoke check are real accepted pre-production gaps but are hidden behind a declaration of no gaps.
   - Remediation: record these under canonical `Verification Gaps` with their accepted deployment gate and remove the competing deferred-verification sections.

### SUGGESTION

1. **Normalize manual evidence status wording (`workflow-drift`)**
   - References: LC-001 manual evidence rows and related closed Change ledgers.
   - Impact: variants such as `Confirmed` and `confirmed by user` diverge from canonical `user confirmed` vocabulary.
   - Remediation: normalize wording without changing dates or acceptance meaning.

2. **Declare requested-route resumption (`requirement-drift`)**
   - References: `SignInPage.tsx` and `App.test.tsx`.
   - Impact: successful sign-in resumes the originally requested protected route, including query and fragment, but S2 promises only the World workspace.
   - Remediation: add a focused Scenario if this remains accepted product behavior.
